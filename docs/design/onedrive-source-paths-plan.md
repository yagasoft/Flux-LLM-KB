## Diagnosis and design

The baseline `SourceRootPathPolicy` rejects any reparse point in an ancestor. `PhysicalFileIdentity.EnsureNoReparsePointTraversal` repeats that rejection during scan revalidation. `LocalSourceEnumerator.CollectFiles` skips every reparse entry. The direct `Utf8FileSourceReader` tries to resolve every reparse folder as a symbolic link. Source retention opens the original file again, so admission alone is insufficient.

Microsoft identifies `0x9000601A` and `0x9000701A` as Cloud Files tags. The exact supported family is `IO_REPARSE_TAG_CLOUD` through `_F`; accept only these recognised non-name-surrogate tags, not every Microsoft tag or every non-link tag. Read attributes and tags from metadata/no-follow handles using `GetFileInformationByHandleEx(FileAttributeTagInfo)`. Tag lookup failures fail closed. Folder names and OneDrive environment variables are not evidence of safety. See [Microsoft reparse tags](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/c8e77b37-3909-4fe6-a4ea-2b9d423b1ee4) and [handle attribute/tag information](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_attribute_tag_info).

Introduce a small source-only Windows path-access helper, with a narrow injectable native metadata/open boundary for deterministic tests. Retain strict defaults in `PhysicalFileIdentity.OpenReadNoFollow`, `OpenDirectoryLease`, `GetProjectedPhysicalPath`, `ContainedFileReader` and artifact destination validation. Do not globally relax a helper also used for deployment, deletion, cache, retained storage or Git control metadata.

For source access, validate each ancestor, hold the necessary directory handles through use, inspect the final file handle and verify final path, volume/file identity and containment before reading bytes. Revalidate the admitted root identity at scan and retention boundaries. Reject symlinks, junctions, mounted-folder escapes, unknown tags, changed identities and protected overlaps on the source-root path. Preserve the direct ingress reader's existing authorised alias/containment contract and escape tests while recognising cloud folders without `ResolveLinkTarget`.

Treat path safety and content availability separately. Inspect offline/recall state before data access and again on the actual read handle; partial, inaccessible or provider-unavailable files are unavailable, not deleted or successfully indexed. Do not call hydration/pinning APIs. Native reads must have a verified no-recall/availability guard; a prior attribute check or a generically named no-recall flag alone is not proof against an availability race. Prove the selected opening/lease strategy in an isolated Windows placeholder fixture before allowing cloud content reads. If the platform cannot provide that guarantee, fail closed for the affected state and report the limitation. [Microsoft file attributes](https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants) distinguish recall on open from recall on data access, including directory enumeration.

Independent review corrections: use parent-relative native opens to bind each child to its held parent; use no-follow/no-recall opens, with read sharing only on content handles. Reject both `CF_PLACEHOLDER_STATE_PARTIAL` and `PARTIALLY_ON_DISK`, invalid state and offline/recall flags; do not require `IN_SYNC`. The read lease addresses a conforming provider's exclusive dehydration operation, not arbitrary kernel activity. Bounded directory namespace population is distinct from file-content hydration; do not promise zero provider/network activity. Retention-time unavailability must also prevent unseen-revision suppression. Test the real dehydration conflict and account for actual read bytes, not merely classification-buffer size.

Preserve `SourceEnumerationEvidence` and the existing rule in `SourceScanWorker`: incomplete scans cannot suppress unseen revisions. Add stable, specific reasons for cloud content unavailable, provider/access failure and unsupported reparse type. Continue indexing available siblings. No new persistent state or schema is expected.

Preview currently invokes the full hashing enumerator, and collection materialises the entire tree before returning files. Give Preview an explicit bounded scan path: at most 256 visited entries, 16 candidate files, 16 MiB aggregate data and a 5-second cooperative deadline. Enforce budgets during traversal and before opening content, honour exclusions before descent, and show when results are sampled/incomplete. The deadline is not a guarantee that synchronous Windows metadata calls can be interrupted. Do not label estimates or unavailable items as an empty folder or completed indexing. Regular authorised ingestion retains its configured policies and cancellation semantics.
